Model penalaran (reasoning) dirancang untuk "berpikir" sebelum berbicara. Berbeda dengan model chat standar yang memprediksi token berikutnya secara instan, model penalaran menghasilkan urutan pemikiran internal (chain-of-thought) untuk membedah instruksi kompleks, memverifikasi fakta, dan mengoreksi logika mereka sendiri sebelum menyajikan jawaban akhir.

## Field `reasoning_content`

Neosantara menyediakan antarmuka terpadu untuk penalaran di seluruh penyedia model. Terlepas dari apakah model menggunakan blok native atau tag khusus (seperti `<think>`), Neosantara menormalkan output ini ke dalam field khusus **`reasoning_content`** dalam respons API.

---

## Cara Kerjanya

Neosantara menggunakan tiga mekanisme berbeda untuk mengaktifkan penalaran, tergantung pada kemampuan model tersebut.

### 1. Penalaran Native (Asli)
Model yang dilatih khusus untuk penalaran, seperti **DeepSeek-R1**, **Claude 3.7**, dan **Gemini 2.0 Flash Thinking**, menggunakan logika bawaan mereka. Neosantara terhubung langsung ke protokol "berpikir" native ini untuk memastikan kualitas pemikiran tertinggi.

### 2. Injeksi Instruksi (Instruction Injection)
Untuk model standar yang tidak memiliki penalaran native (misalnya, `garda-core`, `archipelago-core-70b`), Neosantara menggunakan **Injeksi Instruksi**. Saat penalaran diaktifkan, sistem secara otomatis menambahkan instruksi logika kompleks ke prompt sistem, memaksa model untuk membedah prosesnya ke dalam beberapa langkah.

### 3. Upaya Penalaran & Toggle (`reasoning_effort`)
Neosantara menstandarkan kontrol penalaran di seluruh model yang didukung melalui parameter yang kompatibel dengan OpenAI: **`reasoning_effort`**. Anda dapat mengirimkan `reasoning_effort` dalam body request untuk mengatur kedalaman pemikiran atau mematikan penalaran sepenuhnya pada model yang mendukung toggle.

| Tingkat Upaya | Deskripsi | Perilaku |
| :--- | :--- | :--- |
| `none` | **Menonaktifkan pemikiran/penalaran**. | Mematikan proses chain-of-thought pada model toggleable (misalnya `claude-sonnet-5`, `gpt-5.4`, `deepseek-v4-flash`, `kimi-k2.6`, `glm-4.5-flash`). Mengembalikan jawaban langsung tanpa token penalaran. |
| `minimal` | Proses penalaran tercepat. | Pemeriksaan logika ringan dan refleksi singkat. |
| `low` | Chain-of-thought cepat. | Tugas pengodean dasar, instruksi multi-langkah dengan latensi rendah. |
| `medium` | Penalaran seimbang standar. | Pemecahan masalah umum, debugging kompleks, kecepatan dan kedalaman seimbang. |
| `high` | Penalaran analitis mendalam. | Logika sulit, pembuktian matematis, perencanaan arsitektur. |
| `xhigh` | Penalaran frontier tingkat lanjut. | Rekayasa perangkat lunak jangka panjang dan refaktorisasi berat. |
| `max` | Kedalaman maksimal. | Eksplorasi penuh model untuk tugas-tugas paling menantang. |

#### Contoh: Melakukan Toggle Penalaran via SDK

```javascript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'https://api.neosantara.xyz/v1',
  apiKey: process.env.NEOSANTARA_API_KEY
});

// 1. Matikan penalaran (untuk model toggleable)
const nonThinkingResponse = await client.chat.completions.create({
  model: 'claude-sonnet-5',
  messages: [{ role: 'user', content: 'Apa ibu kota Perancis?' }],
  reasoning_effort: 'none'
});

// 2. Kontrol kedalaman pemikiran
const thinkingResponse = await client.chat.completions.create({
  model: 'claude-sonnet-5',
  messages: [{ role: 'user', content: 'Rancang mekanisme konsensus terdistribusi.' }],
  reasoning_effort: 'high'
});
```

### Pelaporan Token
Token penalaran dilacak secara terpisah dari jawaban akhir untuk memberikan transparansi yang lebih baik tentang penggunaan dan biaya.
*   **Format OpenAI**: Dilaporkan di `usage.completion_tokens_details.reasoning_tokens`.
*   **Responses API**: Dilaporkan di `usage.output_tokens_details.reasoning_tokens`.
*   **Billing**: Token penalaran ditagih dengan tarif yang sama dengan token output standar untuk sebagian besar model.

## Praktik Terbaik

1. **Gunakan Streaming**: Proses penalaran dapat menghasilkan ribuan token internal sebelum jawaban akhir muncul. Gunakan [Streaming](/id/capability/stream) untuk memberikan umpan balik visual waktu nyata ("Sedang berpikir...") kepada pengguna Kamu.
2. **Spesifik, Bukan Deskriptif**: Berikan tujuan yang jelas kepada model penalaran, tetapi hindari mengatur setiap langkahnya secara mikro. Biarkan model menentukan jalur optimal menuju solusi.
3. **Atur Anggaran dengan Bijak**: Lebih banyak token penalaran akan meningkatkan latensi dan biaya. Hanya alokasikan anggaran tinggi (>10rb) untuk tugas sains atau matematika yang benar-benar kompleks.
